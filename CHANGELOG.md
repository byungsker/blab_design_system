# Changelog

All notable BLDS changes will be documented here. The package has not been
released or published.

## [0.2.0] - Unreleased

### Added

- Repository-owned typed primitive, semantic, and component token contracts,
  deterministic Flutter/CSS/documentation generation, and drift checks.
- Additive light, dark, high-contrast, interaction, semantics, focus, text
  scaling, reduced-motion, haptic, and overlay foundations.
- Sequential local remediation evidence for the nine existing public component
  families, plus a complete story/state manifest and ten Design-approved local
  candidate baseline identities.
- Analyzer-backed public API snapshots and an immutable `HEAD`-derived Phase 5
  compatibility baseline.
- A 0.x API/token compatibility policy, deterministic additive/breaking
  classifier, explicitly unsupported and unknown deprecated detection,
  migration registry, disposable no-source-rewrite rehearsal, and
  repository-artifact rollback verification.
- File-level origin inventory, root third-party notice, Astryx 0.1.3 evidence
  packet, SPDX 2.3 and CycloneDX 1.6 local dependency inventories, and unsigned
  human-attestation templates.

### Changed

- `BLabPressableWrapper` preserves the legacy non-null public `onTap` field
  while a private nullable callback retains noninteractive behavior when a
  caller supplies `null`. Existing field reads and invocations remain safe.
- Additive optional component parameters and shared foundations preserve the
  committed `HEAD` call surface. The two approved standard-mode Button
  foreground value corrections are explicitly breaking compatibility
  corrections under `BLDS-BUTTON-CONTRAST-2026-07-28`; current classification
  is 469 additive and 2 breaking changes. Deprecated detection is not
  implemented in Phase 5, so its result is typed unknown rather than zero.

### Known limitations and blockers

- `0.2.0` is the accepted repository-only target and remains local and
  unreleased; no merge, tag, release, or publication is authorized.
- Phase 5 exit is false. Remote CI, two clean pinned direct
  Flutter consumers, rights/notice and transfer authority, contributor
  restrictions, canonical custody, package composition, production font
  strategy, origin attestations, markets/channels/jurisdictions, and final
  release authority remain unresolved.
- OpenCS is a web-adapter experiment, not a direct Flutter consumer.
- Local tests, analyzer results, diagnostics, SBOMs, or golden equality do not
  establish accessibility, visual, locale, platform, legal, release, or
  publication conformance.
